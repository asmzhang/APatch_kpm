# hide_env 路线否决记录（2026-10-29）

## 结论

`hide_env`（上游 `kpm-hide-env` 1.0.7 的移植与后续 1.1.0 改造）**不进入交付集**，代码删除，仅保留本记录。

## 否决理由（结构性，不是参数问题）

1. 实现方式是把“要隐藏的路径”写成字面量表（`/system/bin/su`、`/data/adb/ap` 等十余条），再按 syscall 号逐个拦截。隐藏集的来源是“读了某个检测器的源码”，属于 oracle 泄漏：对方换实现即失效，且与设备、root 方案强绑定。
2. 拦截点选在 syscall 入口，覆盖集是开集（56/48/79/291/437/439 … 后面还会有），不可能闭合。

## 实测证据（P6 `sha256:433ab88276ec`，6.1.99，内建 KernelPatch，管理器 uid 10273）

| 版本 | 产物 | 现象 |
| --- | --- | --- |
| 1.0.7 | 8,592 B | openat 生效，stat 家族无效 |
| 1.0.8 | 9,392 B | 补 openat2/faccessat2，无效 |
| 1.0.9 | 9,872 B | 补 basename 匹配，无效 |
| 1.0.10 | 9,688 B | 关掉 437/439，无效 |
| 1.1.0 | 12,400 B | 增挂 `vfs_statx`/`vfs_fstatat`，`hook` 返回 0 但 `hits` 始终为 0 |

同一设备上 `hosts_redirect` 挂 `do_filp_open` 生效，证明函数级钩子机制本身可用；问题在选中的符号是否真的在执行路径上（`vfs_statx` 很可能被内联进 `sys_statx` 的副本）。

检测器（runtime-sense）总分在五个版本间始终为 86/9/4/7，未发生任何变化——说明该检测器对这组改动不敏感，用它当记分板无法指导迭代。

## 替代方向

按“不可区分性”模型重做：隐藏集取命名空间差集（按 dev/inode 判等，不写路径字面量），拦截点下移到名字解析的唯一入口，枚举与自述通道共用同一谓词，验收用从模型导出的不变量测试而非检测器分数。
