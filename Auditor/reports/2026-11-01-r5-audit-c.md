## 2. 逐条复核（证据）

### 2.1 memcrc

**AUD-a-1（critical，REMOVE TYPE 栈溢出）——已修好。**
`data/parser.c:115-131`：先取 `type_len = colon_pos - arg2`、`index_len = strlen(colon_pos+1)`，`parser.c:120-121` 校验 `type_len == 0 || type_len >= sizeof(type_str) || index_len >= sizeof(type_index_str)` 即返回 `PARSER_ERR_PARAM`；随后 `parser.c:127-130` 用定长 `memcpy` + 显式 `\0`。原 `strncpy(type_str, arg2, colon_pos-arg2)` / `strcpy(type_index_str, ...)` 已在 diff（`git show ee8f97f -- modules/KPM/memcrc/data/parser.c`）中删除。arg2 上限 255（parser.c:53），16 字节缓冲 + `>=` 比较无 off-by-one。两条入口（/dev 通道、ctl0）均被覆盖。无新引入问题。

**AUD-a-2（critical，/dev/yuuki_misc 无鉴权通道）——已修好。**
- `komm/komm.c:313-319`：`.mode = 0600`（注释自指 AUD-a-2），普通进程 open 不到。
- `komm.c:290-298`：`on_misc_open` 取 `control_current_uid()` 并要求 `control_is_privileged`，否则 `-EPERM`。
- `komm.c:47-51`：write 命令路径前置 `if (!control_is_privileged(control_current_uid())) return -EPERM;`。
- `komm.c:65-66`：数据路径改走 `shared_data_add_parsed_scoped(yuuki, uid, privileged)`，原 `shared_data_add_parsed`（shared_data.c:299-302，写死 uid=0/privileged=true）在 misc 通道不再可达（grep 全模块仅 mod_main.c:91 ctl0 路径调用，ctl0 本身在 superkey 门后）。
- 信任表与 getcwd 通道同源（control.c:28-29 `{0, 2000}`），无双源漂移。
残余：mode 0600 使 uid 2000 无法直连设备节点（r4-review-a 已判可接受，维持）。

**AUD-a-3（high，seq 扩容越界写）——已修好。**
`ptrace/ptrace_hide.c:329-340`：扩大分支先算 `need = new_len - replace_len`，`ptrace_hide.c:333` `if (m->count + need > m->size)` 命中即 `pr_warn` + 直接 `return ret`（不改 m->count），否则才 `memmove` + `m->count += need`（:337-339）。缩小分支（:325-328）与 TracerPid 分支（:349-374，只缩小）本就安全。扩大后 `memcpy(state_value, replacement, new_len)`（:342）落在已确认的余量内。无新问题。

**AUD-a-4（low，init 假成功/回滚缺失）——已修好。**
`mod_main.c:22-61`：`init_symbols()` 失败 `-ENOENT` 拒载；五个子系统逐个判错，失败按初始化逆序回滚（feature→ioctl；redirect→feature→ioctl；syscall→redirect→feature→ioctl；ptrace→syscall→redirect→feature→ioctl），全部返回 `-EIO`。`mod_exit`（:118-126）无条件 exit 现在安全：可达 exit 即全部初始化成功。

**AUD-a-5（low，read 无上限/strcat）——已修好，但发现相邻新单 AUD-c-10。**
`komm/komm.c:97-99` `#define MC_READ_MAX (64*1024)`；`komm.c:119-121` clamp 后才 `kf_vmalloc`；全部输出改为 `snprintf(temp,512)` + 前置 `total_len + temp_len < count` 守卫的 `memcpy`（:135-263）。**新问题见 §3 AUD-c-10：空表覆盖分支（komm.c:265-272）的 `total_len = temp_len` 未按 count 钳制。**

**AUD-a-6（info，NUL 顺序/返回值）——已修好。**
`mod_main.c:104-111`：`if (len >= outlen) len = outlen - 1;` → `buf[len] = '\0';`（内核侧先补 NUL）→ `compat_copy_to_user(out_msg, buf, len + 1)`，失败 `-EFAULT`。`len+1 <= outlen` 恒成立，无越界。

### 2.2 stealth_hook（边界确认，深度归 B 组）

- **ghost/HWBP 命令门**：`stealth_hook.c:143-153`——非 root 时 `[SH_CMD_HWBP_HOOK 0x1001, SH_CMD_HWBP_SET_SKIP 0x1007]` 与 `[SH_CMD_GHOST_ALLOC 0x3001, SH_CMD_GHOST_LIST 0x3004]` 两个区间判断返回 -1；与 stealth_hook.h:40-46、:69-72 的命令定义逐一比对，区间端点正确、无缝隙（0x1001-0x1007 连续、0x3001-0x3004 连续）。PTE 命令（0x2002-0x2004）对所有 uid 一律 `-EOPNOTSUPP`（:168-175），无能力差异。STATUS/ECHO/PTE_QUERY 对 shell 开放，仅回显版本/幻数，无副作用。

## 3. 新增问题单

### AUD-c-7　mount_hidder：hm_after 命中边界检查可读到 m->buf[m->size]（1 字节越界读）
- **severity**：low
- **位置**：modules/KPM/mount_hidder/hide_mount.c:181-187
- **机制**：`hit = strnstr(m->buf + base, hm_paths[i], len)`，`len = m->count - base`。前置守卫只排除 `m->count > m->size`（:175），允许 `m->count == m->size`。当某条挂载项恰好写满 seq 缓冲且命中路径的结尾就在 `m->buf + m->count - 1` 时，`hit[plen]` 的下标为 `m->count`，即读 `m->buf[m->size]`——精确分配的 seq_file 缓冲越后 1 字节（与 AUD-c-4 同类，但只读不写）。
- **证据**：hide_mount.c:175（守卫为 `>` 而非 `>=`）、:187（`hit[plen] == ' ' || hit[plen] == '\0'` 无 `hit + plen < m->buf + m->count` 前提）；对照 panda_hide 修复（frida_hide.c:34）已规避同型问题。
- **frequency**：low（需缓冲恰好写满且匹配收尾于末端）
- **confidence**：high（下标演算确定；目标内核 seq_file 是否 size+1 分配未核实）
- **修法建议**：边界读改为 `hit + plen < m->buf + m->count && (hit[plen]==' ' || ...)`，或先判 `m->count < m->size` 才做该匹配。

### AUD-c-8　mount_hidder：clear 整词匹配漏 `\t`/`\r`，与 stealth_hook 同类实现不一致
- **severity**：low
- **位置**：modules/KPM/mount_hidder/hide_mount.c:268-269
- **机制**：`args[5]` 只认 `\0`/空格/`\n`；`clear\t<任意>` 仍执行清空。对照 stealth_hook.c:364-373 `sh_is_word` 覆盖四种空白。行为混淆类，无内存安全问题。
- **证据**：两处源码行号如上。
- **修法建议**：抽同一整词判定或补 `\t`/`\r` 两个分支。

### AUD-c-9　qti / xperia：debug 变体无任何门控调试代码，debug == release（仅版本串不同）
- **severity**：low
- **位置**：modules/KPM/qti_battery_charger/Makefile:43-44、modules/KPM/xperia_ii_battery_age/Makefile（同构）；源码 0 处 `DEBUG`/`logkd` 消费（xperia 唯一 logkd 在 xperia_ii_battery_age.c:69 注释态）
- **机制**：R4d 给 debug 加了独立对象目录与 `-DDEBUG`，产物因此哈希分离（本轮实测），但源码没有任何 `#ifdef DEBUG`/logkd 门控路径，debug 相对 release 的差异仅为嵌入版本串 `_d` 与派生重定位。按 AGENTS §4.1「debug 相对 release 只增加日志/断言详细度」的验收前提，此处差异不成立，「真机只测一个变体」的免测依据落空。
- **证据**：`cmp -l` 差异字节数 qti 109 / xperia 2053；`llvm-readelf -p .kpm.info` 两 debug 件 version 带 `_d`；grep 无门控代码（命令与计数见 §0）。
- **修法建议**：给两模块补少量 `#ifdef DEBUG` 的入参/寄存器值日志使变体有实义；或按规范砍掉 debug 目标并在 metadata 标注。

### AUD-c-10　memcrc：my_read 空表覆盖分支 total_len 未按 count 钳制，可越界读 vmalloc 缓冲并泄露给用户
- **severity**：medium（确认可致内核堆越界读 + 向用户态泄露相邻内存；可达性受 AUD-a-2 修复后的特权门限制，不因频率未知降级）
- **位置**：modules/KPM/memcrc/komm/komm.c:265-278
- **机制**：`count` 较小（< ~57 字节）时各段 header 写不下 → `goto buffer_full`。`komm.c:267-272`：当 `total_len == 0` 或所有计数为 0，执行 `temp_len = snprintf(kernel_buf, count, "[MAPPINGS:0]...[END]\n"); total_len = temp_len;`——snprintf 返回值是**本应写入的完整长度**（49），不是实际写入字节数；`count < 49` 时 `total_len > count`。随后 `komm.c:274` `compat_copy_to_user(buf, kernel_buf, total_len)` 从 `kf_vmalloc(count)` 的小缓冲越界读 `(49 - count)` 字节堆内存并拷给用户态（信息泄露）；`count` 极小时还叠加 `total_len==0` 分支对分配失败/零尺寸缓冲的拷贝风险。此外该分支在「条目非空但第一条 header 都写不下」时会把非空表误报为全零（`total_len==0` 触发覆盖，:267）。
- **证据**：komm.c:119-127（clamp 只保证分配 ≤64KiB，不管下限）、:265-272（`total_len = temp_len` 无 `min(temp_len, count)`）、:274-278（按 total_len 拷贝）。手推 `read(fd, buf, 30)`：13+10+10=33<50 前两段后 `[RANGES:0]\n` 43>30 → buffer_full，total_len=13+10+10=33… 进入全零覆盖分支，snprintf(buf,30,…49 字符) 返回 49，copy 49 字节。
- **frequency**：low（需特权调用者发起小 count read；/dev 节点 0600 且 open/write 均有 uid 门）
- **confidence**：high（长度演算逐字节可复算；未真机复现）
- **修法建议**：覆盖分支改为 `total_len = min((size_t)temp_len, count - 1)`（或预判 `count < 49` 时直接返回 `-ENOSPC`/短回复），并处理 `total_len == 0` 但表非空的误报路径。
