## 4. 问题单

### AUD-a-1　`CMD:REMOVE:TYPE:` 命令导致内核栈溢出
- **位置**：modules/KPM/memcrc/data/parser.c:115-117（`parser_handle_remove_command`），入口 parser.c:87 `char type_str[16] = {0};`
- **影响**：`arg2` 由 parser_parse_command_args（parser.c:52-54）填充，最长 255 字节；`strncpy(type_str, arg2, colon_pos - arg2)` 的长度参数 `colon_pos - arg2` 完全由输入决定，可达 ~255，而目标 `type_str` 仅 16 字节。发送 `CMD:REMOVE:TYPE:<17 个以上任意字符>:N` 即可对内核栈进行最长约 240 字节的越界写，可破坏栈上数据/返回地址，潜在可致崩溃或本地提权。
- **severity**：critical（确认可致内核内存越界写，安全影响上限为提权）
- **frequency**：确定性触发——每条畸形命令必触发，无竞态或概率成分
- **confidence**：high（代码级逐行复算；未真机验证，但路径无任何长度守卫）
- **验证方法与证据**：通读 parser.c；`arg2[256]`（parser.c:271）、`type_str[16]`（parser.c:90）、无长度检查的 `strncpy(type_str, arg2, colon_pos - arg2)` 与 `type_str[colon_pos - arg2] = '\0'`（parser.c:115-116，越界下标写再 +1）；`strcpy(type_index_str, colon_pos + 1)`（parser.c:117）在冒号后超 15 字节时同溢 `type_index_str[16]`。可达通道：KPM_CTL0（mod_main.c:48，superkey 门后）与 /dev/yuuki_misc write（komm.c:46-48，见 AUD-a-2，无门）。
- **建议修复方向**：先 `if (colon_pos - arg2 >= sizeof(type_str)) return PARSER_ERR_PARAM;`（对 type_index_str 同样校验），或改用 `strscpy`/显式长度解析。

### AUD-a-2　/dev/yuuki_misc（mode 0666）为无鉴权特权规则注入通道，绕过 getcwd 通道的作用域门
- **位置**：modules/KPM/memcrc/komm/komm.c:296-301（miscdevice `.mode = 0666`）、komm.c:60（`shared_data_add_parsed(yuuki)`）；modules/KPM/memcrc/data/shared_data.c:299-302（`shared_data_add_parsed` 写死 `shared_data_add_parsed_scoped(str, 0, true)`，privileged=true、uid=0）；对照 modules/KPM/memcrc/control/control.c 的 getcwd 通道（按调用者 uid 与受信表限定作用域）。
- **影响**：任何能 open /dev/yuuki_misc 的进程（设备节点权限 0666，on_misc_open 无 uid/context 检查）可写入 `MAP:<任意uid>:src:dst`、`PATH:`、`PTRACE:`、`REGS:`、`RANGE:` 以及全部 CMD 管理命令，包括添加全局规则与操纵任意 uid 的隐藏/重定向条目——完全绕过 control.c 为 getcwd 通道设计的作用域门，并可直接到达 AUD-a-1 的溢出。等效于把模块管理能力暴露给任意本地进程。
- **severity**：critical（安全边界缺失；可达性受下述未核实项影响，按 AGENTS 规则不因频率未知降级）
- **frequency**：未知（取决于设备上 SELinux 策略是否允许相应 context 访问该 misc 节点；代码层面 open 无任何门）
- **confidence**：high（代码级确认 privileged=true 与 0666、无 open 检查；**SELinux/sepolicy 实际可达性未核实**——审计环境无法枚举目标设备策略，untrusted_app 域默认未必能 open 自定义 misc 节点）
- **验证方法与证据**：komm.c:296-301 `.mode = 0666`；komm.c:278-281 on_misc_open 直接 return 0；komm.c:60 数据路径 `shared_data_add_parsed`；shared_data.c:299-302 注释自述「调用方已经是受信身份」但 misc 通道并不成立；对照 control.c getcwd 通道存在受信/作用域判断。
- **建议修复方向**：misc 节点改为 0600/0660 并在 open/write 校验调用者（is_su_allow_uid / 受信管理器 uid，或要求特定 scontext）；或移除 misc 通道、统一走有作用域门的 getcwd/ctl0 通道；至少为 misc 通道复用 shared_data_add_parsed_scoped 的非特权路径。

### AUD-a-3　rep_proc_pid_status 状态行替换可越界写 seq_file 缓冲（未校验 m->size / 剩余空间）
- **位置**：modules/KPM/memcrc/ptrace/ptrace_hide.c:325-335（扩大分支 `memmove(line_end + (new_len - replace_len), line_end, m->count - (line_end - m->buf)); m->count += (new_len - replace_len);`），并依赖其后 `memcpy(state_value, replacement, new_len)`（:335）写入增量区域。
- **影响**：替换值 "R (running)" 长 11 字节。当目标进程为 zombie 时原 State 值 "Z (zombie)" 仅 10 字节 ⇒ 走 `new_len > replace_len` 扩大分支：先 memmove 把行尾整体右移 1 字节、再写入 11 字节。整个过程不检查 `m->buf` 容量（m->size）或缓冲剩余空间；若此刻 seq 缓冲已满（count==size），右移与写入都落在 `m->buf + m->size` 之外的内核堆内存，造成越界写。其它更长 State 值（S/D/T 等 ≥12 字节）走缩小分支，安全；因此触发窗口窄但真实存在。
- **severity**：high（确认可致内核堆越界写，可致崩溃/内存破坏）
- **frequency**：low（需目标进程恰处于 zombie 态且 seq 缓冲恰满这两个条件同时成立）
- **confidence**：high（代码级复算 memmove/写方向与字节数；未真机复现）
- **验证方法与证据**：ptrace_hide.c:321-323 `replace_len = line_end - state_value`、`replacement = "R (running)"`、`new_len = 11`；:329-333 扩大分支无任何 `m->size` 比较；:335 `memcpy(state_value, replacement, new_len)`。对照同文件 TracerPid 分支（:359-365）只会缩小，安全。
- **建议修复方向**：扩大分支前校验 `m->size - m->count >= (size_t)(new_len - replace_len)`，不足则跳过替换（或仅缩小方向替换）；校验失败时不修改 m->count。

### AUD-a-4　mod_init 符号解析失败仍返回 0，且 mod_exit 与未初始化路径不配对
- **位置**：modules/KPM/memcrc/mod_main.c:21-36（`if(init_symbols()) { pr_info(...); goto exit; }` 后 `return 0;`）、mod_main.c:89-97（mod_exit 无条件调用 ioctl_exit/feature_exit/redirect_exit/syscall_exit/ptrace_hide_exit）。
- **影响**：kallsyms 任一符号缺失时模块仍以「加载成功」返回，但所有子系统未初始化；此后卸载时 mod_exit 仍对未初始化子系统调用各 *_exit（如 misc_deregister 未注册的设备），行为依赖各 exit 的容错性，且运维侧难以从加载结果判断模块实际失效，误判为「已生效」。
- **severity**：low
- **frequency**：unknown（仅在目标内核缺少被解析符号时发生）
- **confidence**：high（代码级确认控制流）
- **验证方法与证据**：mod_main.c:23-26 失败仅打日志即 goto exit，exit 标签处 `return 0`；symbols.h 中 init_symbols 任一符号缺失返回 1。
- **建议修复方向**：init_symbols 失败时返回负值（或至少 pr_err 并在 embedded 状态中标记失效）；各 *_init/exit 记录初始化位图，exit 只回滚已初始化部分。

### AUD-a-5　my_read 按用户可控 count 直接 kf_vmalloc，任意进程可触发大额内核分配（DoS 面）
- **位置**：modules/KPM/memcrc/komm/komm.c:111-115（`kernel_buf = kf_vmalloc(count); memset(kernel_buf, 0, count);`）
- **影响**：count 来自用户 read 长度，无上限；结合 AUD-a-2 的无鉴权通道，任意进程可用一次大 count read 触发大额 vmalloc + 全量 memset（配合反复调用可放大），造成内存压力/分配失败路径。数据实际填充远小于 count（受条目数限制），但分配与清零按 count 执行。
- **severity**：low
- **frequency**：unknown（取决于是否有进程实际发起；代码层面无门槛）
- **confidence**：high（代码级确认无上限）
- **验证方法与证据**：komm.c:102-115：仅 `*pos > 0` 短路与初始化检查，count 无 clamp。
- **建议修复方向**：对 count 设合理上限（如 clamp 到 64KiB）或先按条目统计估算实际需要再分配。

### AUD-a-6　mod_control0 out_msg 截断无 NUL，且未检查 compat_copy_to_user 返回值
- **位置**：modules/KPM/memcrc/mod_main.c:77-83
- **影响**：`len > outlen` 时截断为 outlen 字节，拷贝内容不含 NUL，用户态若按字符串处理可能越界读（信息面轻微）；`compat_copy_to_user`（KP 语义：返回拷贝字节数，0=失败，声明 `__must_check`，见 KernelPatch/kernel/patch/common/utils.c:74-98）返回值被忽略，拷贝失败时调用方得不到错误指示。均为正确性/健壮性问题，无直接安全影响。
- **severity**：info
- **frequency**：low（仅长响应 + 小 outlen，或用户指针无效时）
- **confidence**：high
- **验证方法与证据**：mod_main.c:77-83；KP utils.c:74-97 实现与 kputils.h:12 `__must_check` 声明。
- **建议修复方向**：截断时保留 1 字节给 NUL（len = outlen - 1）；检查 compat_copy_to_user 返回值并回传 -EFAULT。
