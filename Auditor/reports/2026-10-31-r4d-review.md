## 逐条复核

### 1) AUD-b-7（stealth_hook ctl0）—— 关闭

- 有界性：`sh_parse_uid`（stealth_hook.c:319-352）`++digits > 10` 拒绝超长、`v > 0xFFFFFFFFUL` 拒溢出、非数字结尾（含尾随垃圾）返回 0 —— 有界 ✅。
- snprintf 返回值：累加统一走 `sh_app`（:383-401），`w >= cap - n` 时回 `cap`（饱和，不再增长），`w < 0` 回 `n`；不再把截断值加回 n ✅。
- 整词匹配：`sh_is_word`（:368-378）要求命令后是 `\0`/空格/tab/换行；`statusXXX`、`allowlistXXX` 落入 handled=0 → 返回 -1 ✅。
- 后续链：`sh_dump_allow`（:95-104）内部 `n < (int)out_size` 守卫 + kf_snprintf；`sh_app` 饱和后 `buf + n` 不会越过 `buf+cap`，`sizeof(buf) - n` 不会为负（n==cap 时 sh_app 直接返回 cap，不再写）✅。

### 2) AUD-b-8 / AUD-b-9（mount_hidder）—— 关闭

- b-8：hide_mount.c:181-190，命中处前一字节是行首或 `' '`、`hit[plen]` 是 `' '` 或 `\0` 才回滚。"/data" 对 "/data_mirror" 因 `hit[5]=='_'` 不命中 ✅。`plen` 在 `len` 界内由 strnstr 语义保证（needle 完整落入前 len 字节），`hit[plen]` 至多读到 `buf+base+len` = `m->buf+m->count` ≤ `m->size`（:173 已挡 `m->count > m->size`），读 `m->count` 位置本身在 size 界内，安全。
- b-9：hide_mount.c:266-267，"clear" 后必须是 `\0`/`' '`/`'\n'`，"clearXXX" 落入 `rc=-2` ✅。未包含 `'\t'`/`'\r'`，tab 分隔的 "clear\t" 会被当未知命令——保守方向（误拒而非误收），不另开单。

### 3) AUD-c-6（panda_hide wchan）—— 关闭

- debugger_hide.c:38-39：`m->count >= 11 && memcmp(m->buf, "ptrace_stop", 11) == 0`，按 count 有界 ✅。`m->count==11`（恰好无 NUL）也安全；改写 `buf[0..1]` 与 `count=1` 在 count≥11 前提下界内。
- 残留观察（info，不阻塞）：`before_seq_puts`（debugger_hide.c:28-31）对 `args->arg1` 字符串字面量做 strcmp 属钩子参数语义，不在本单范围。

### 4) AUD-c-1（qti / xperia Makefile）—— 关闭

- 两 Makefile 均为：`debug_objs := $(addprefix debug/,${objs})`（:41）、debug 目标 `CFLAGS += -DDEBUG` + `QBC_VER := _d` / `XIIBA_VER := _d`（:43-45）、`qti_..._debug.kpm: ${debug_objs}`（:53-54）、独立规则 `debug/%.o: %.c`（:61-63，`@mkdir -p $(@D)`）✅ 真用独立对象目录 + -DDEBUG。
- 变量展开核对：`QBC_VER`/`XIIBA_VER` 是 target-specific 变量，`CFLAGS` 在依赖 `debug/%.o` 编译时展开为含 `-DDEBUG` 且 `-DMYKPM_VERSION=\"..._d\"` —— make 的 target-specific 变量对依赖构建期间展开生效，机制正确。
- 实测哈希：qti release `9b8dfb9a…` vs debug `f35121e0…`（同 6072B，内容不同）；xperia release `f4346ed0…`（6296B）vs debug `2cd53604…`（6304B）。均已不同 ✅。
- AUD-e-5（info）：若 `debug/%.o` 已存在且比 .c 新，`make debug` 不会因「上次以 release CFLAGS 编译过」而重编（make 只看时间戳）；`make clean` 会清掉（`find . -name "*.o"` 覆盖 debug/）。同一棵树先 `make all` 再 `make debug` 时 debug/%.o 是新建的，实际流程安全；仅手工混用时有陈旧风险。
