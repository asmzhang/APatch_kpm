## 1) AUD-c-10（medium）— 结论：已修好

### 1.1 修复本体

`modules/KPM/memcrc/komm/komm.c:269-277`（空表覆盖分支）：

```c
temp_len = snprintf(kernel_buf, count, "[MAPPINGS:0]\n...\n[END]\n");
if (temp_len < 0) { temp_len = 0; }
total_len = ((size_t)temp_len < count) ? (size_t)temp_len : (count > 0 ? count - 1 : 0);
```

`compat_copy_to_user(buf, kernel_buf, total_len)`（komm.c:280）随后使用该 `total_len`。四种边界逐一判定（格式串完整长度 61 字节）：

| 场景 | 逻辑结果 | 判定 |
|---|---|---|
| `count==0` | `snprintf(kb,0,…)→61`，`61<0`? 否 → `count>0`? 否 → `total_len=0`。`copy_to_user(…,0)` 安全返回 0 | 安全。注意 `kf_vmalloc(0)` 可能返回 NULL → 提前 `-ENOMEM`（komm.c:123-126），也不越界 |
| `count==1` | `61<1`? 否 → `total_len = 1-1 = 0`。写入 0 字节，不触碰 `kernel_buf[0]` | 安全（无越界）；行为上返回 0 而非截断 1 字节，见下方 AUD-C-11 备注 |
| 串长==count（如 count=61） | `snprintf` 实际写 60 字节+NUL，返回 61；`61<61`? 否 → `total_len = 60` | 安全且正确：只 copy 实际写入的 60 字节 |
| 串长≫count（如 count=8，真机验证 `head -c 8` 返回 `[MAPPIN` 7 字节） | `61<8`? 否 → `total_len = 7 = count-1`，与 `snprintf` 实际写入的 `count-1` 字节严格一致 | 安全 |

关键不变量：钳制结果 `<= count-1 <= 实际写入字节数`，`copy_to_user` 永不越过 `kf_vmalloc(count)` 缓冲。**AUD-c-10 关闭（已修好）**。

### 1.2 komm.c 全部 snprintf/kf_snprintf 调用点逐个判定

文件中无 `kf_snprintf`。共 14 处 `snprintf`，分三类：

- **写 `temp[512]`、拷贝前判长（12 处）**：komm.c:135、147、161、173、185、197、209、221、235、247、259。模式统一为 `temp_len = snprintf(temp, sizeof(temp), …)` → `if (total_len + temp_len < count) { memcpy; total_len += temp_len; } else goto buffer_full;`。`temp` 定长 512，最大格式（komm.c:147，`%u:%s:%s` + 两个 256 字节路径 + uid）最长 256+1+256+1+10+1 = 525 > 511 → snprintf 返回 525，但 memcpy 只发生在 `total_len+temp_len < count` 且 `total_len < count-512`（循环条件 komm.c:143/169/193/217/243），故 `memcpy(temp, 525)` 读 `temp[0..524]` 会**读越界 13 字节**（栈上），且 `total_len+temp_len < count` 满足时 `memcpy(kernel_buf+total_len, temp, temp_len)` 也可能把 525 字节写入 kernel_buf 剩余不足 525 的空间 —— 需要精确条件：`total_len < count-512` 且 `total_len+temp_len < count`，两者合起来 `temp_len < count - total_len`，而 kernel_buf 剩余空间恰为 `count-total_len`，所以**写不越界**；但 `memcpy(temp, …, 525)` **源读越界 525-512=13 字节**（仅当一条 MAP 规则的 src+dst 接近 512 字节极限时触发）。这是既有问题（非本轮引入，钳制未改变这些分支），单列 AUD-C-11。severity：medium（栈信息泄露 13 字节，条件苛刻：单条规则 src+dst 长度之和 >511）。
  - 位置：`modules/KPM/memcrc/komm/komm.c:147-157`（同模式复制在 173/197/221/247，但这些格式上限 ≤512 不触发）。
  - 建议：`if (temp_len >= (int)sizeof(temp)) goto buffer_full;` 或把 `temp` 扩到 528。
- **komm.c:269（空表覆盖）**：本轮已修，见 1.1。
- **`my_write`（komm.c:27-95）**：无 snprintf；`actual_count` 钳到 `sizeof(yuuki)-1`（komm.c:32），安全。
- **其他文件的 snprintf**（不属于 komm.c 但同模块，顺带判定）：`control/control.c:94-96` 用 `n += snprintf(buf+n, size-n, …)` —— snprintf 返回"本应写入长度"，`size-n` 不足时 n 会越过 size，同 AUD-c-10 同类缺陷；`data/shared_data.c:715/875/1049` 返回值赋给 `len` 后的用法未核实（需查调用方钳制）；`mod_main.c:98-100` 写固定 512 栈缓冲、格式短，安全。** AUD-C-12（medium）：`control.c:94-96` 的累加式 snprintf 存在同类越界写风险，建议同轮修法（按返回值钳制到 `size-n-1`）。
