## mode=0600 的可用性影响（专项说明）

- 设备节点由 misc 框架以 root 属主创建，`0600` 后仅 root（uid 0）可 open。模块受信表 `cm_allow_uids = {0, 2000}`（control.c:28-29）虽包含 uid 2000（shell），但 DAC 在 `on_misc_open` 之前就把 uid 2000 的 open 拒绝（inode 权限检查先于 fops->open），**shell（uid 2000）从此无法直接使用 /dev/yuuki_misc，即使它在模块自己的受信表里**。
- 判定：这构成一个**真实但可接受的可用性收缩**，不作为缺陷单开立，理由：
  1. shell 仍可先经 APatch 的 su（superkey 鉴权，KernelPatch/kernel/patch/common/supercall.c:352 `if (!is_authed) return -EPERM;`、:402-409 superkey 校验）提权为 uid 0 再访问，功能可达性未丧失，只是多一步提权；
  2. 原问题单 AUD-a-2 的严重性正是 0666 + 无门；0600 是「open 层 DAC + open 回调 uid 门 + write 双重门」的纵深修复，方向正确；
  3. 若维护者认为 uid 2000 直连是产品需求，正确做法是 mode 改 0660 并配合属主组（misc 框架不支持设 gid，需评估）或在文档中明示「/dev 通道仅限 root」。此取舍留给维护者，不属于修复错误。
