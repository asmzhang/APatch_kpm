## 逐条复核

### AUD-b-1（HWBP 只给 root）— **仍开**（部分修复）

- 已修部分：`stealth_hook.c:144` 新增 `if (cmd >= SH_CMD_HWBP_HOOK && cmd <= SH_CMD_HWBP_SET_SKIP && sh_current_uid() != 0) { return -1; }`。命令号 `SH_CMD_HWBP_HOOK=0x1001 … SH_CMD_HWBP_SET_SKIP=0x1007`（stealth_hook.h:40-46）连续且都在此区间内，全部 HWBP 命令确实只有 uid 0 可用。PTE 命令本身返回 -EOPNOTSUPP，无影响。
- 残留：原单影响面还包括 `GHOST_WRITE 任意可写页`（r1-b §2 AUD-b-1 原文）。`stealth_hook.h:69-72` 定义 `SH_CMD_GHOST_ALLOC=0x3001 … SH_CMD_GHOST_LIST=0x3004`，全部落在 0x1001–0x1007 区间之外；`sh_dispatch`（stealth_hook.c:169-178）对 ghost 四命令无任何 uid 检查，且新增注释自己写明 "shell(2000) 仍可用 ghost/status"。即 shell 仍可 `sh_ghost_alloc`（在调用者进程里建 RWX 匿名 VMA，ghost_mem.c:95-138）与 `sh_ghost_write`。
- 结论：修复不完整。ghost 子系统是同等危险的内核原语面（RWX 匿名内存分配 + 任意写），仍对 uid 2000 默认开放。若维护者认可「ghost 仅限本进程、shell 用途合理」属设计决策，需在新报告中明示并降级收口；按原单判定为 **仍开**。

### AUD-b-2（断点回调裸解引用用户指针）— **仍开**（方向正确，崩溃面未消除）

- 已修部分：`hwbp.c:284-303`：删除 `msr pan,#0/#1` 与 `*(volatile uint8_t*)(ptr+j)`，改为 `left = sh_copy_from_user(matched->mem_dump[i], (const void *)(uintptr_t)ptr, dn);`（`sh_copy_from_user` 即 kallsyms 的 `__arch_copy_from_user`，hwbp.c:77、:118）。并新增 `if (dn > sizeof(matched->mem_dump[0])) dn = sizeof(...)`（hwbp.c:288-289）钳制拷贝长度；`left <= dn` 才计 `mem_len = dn - left`（hwbp.c:300-302），全失败时 mem_len=0，长度语义正确。坏指针（未映射页）经异常表只少拷不再 panic——原单描述的直接 panic 路径已消失。
- 残留：`hwbp_handler` 运行在 perf 溢出回调（调试异常）上下文，r1-b 已确认"原子、不可睡眠"（hwbp.c:207 注释自认）。`__arch_copy_from_user` 只保证**坏指针不崩**，不保证不缺页：当 ptr 指向的页存在映射但需要 fault-in（换出页、按需填充页）时，copy 路径会走 `do_page_fault` → 可能睡眠/调度，在原子上下文触发 "BUG: scheduling while atomic" 或锁依赖异常，仍可致内核异常。修复前直接 panic、修复后窄化到缺页场景，但未做 `pagefault_disable()`/`probe_kernel_read` 语义兜底。
- 结论：**仍开**（severity 建议降为 medium-high：触发前提从"任意坏指针"收窄为"页映射存在但需 fault-in"）。

### AUD-b-3（链表并发：节点退役不摘链）— **仍开**（单点缓解 + 两条新问题）

- 已修部分：`hwbp.c:119-121` 新增 `int retired;` 字段；`sh_hwbp_unhook`（hwbp.c:415-419）不再 `pos->prev->next = pos->next; … sh_vfree(node)`，改 `node->retired = 1; node->is_disabled = 1;`；handler 遍历处（hwbp.c:215、:219）跳过 retired 节点。unhook 路径的"边遍历边 free"UAF 窗口确实收窄。
- 残留 1（原单核心）：全文件仍无任何锁。`grep -n 'spin\|mutex\|rcu\|_lock' modules/KPM/stealth_hook/hwbp.c ghost_mem.c` 仅有 `perf_event_disable/enable` 字样。进程上下文 `sh_hwbp_hook` 插链（hwbp.c:428-431）与原子上下文 `hwbp_handler` 遍历（hwbp.c:213-221）仍并发无保护；`retired=1` 是非原子的普通写，无法阻止 handler 正在读该节点时 unhook 并发释放其 perf 事件。
- 新问题 2（本次修复引入，新）：**重复 unhook 双重释放**。`sh_hwbp_unhook`（hwbp.c:404-421）不检查 `node->retired`：第一次 unhook 已 `perf_event_release_kernel(node->bp_handle)`（hwbp.c:410-411），节点仍留在链上；第二次同参 unhook 再次匹配该节点并对已释放句柄再调一次 release → perf 事件双重释放（崩溃/UAF）。unhook 成功返回 0 后句柄指针不清零，问题必然可复现（同一 CLI 命令重发即触发）。
- 新问题 3（本次修复引入，新）：`sh_hwbp_enable`（hwbp.c:427-441）、`sh_hwbp_query`（hwbp.c:466-）、`sh_hwbp_set_override`、`sh_hwbp_set_skip` 的匹配循环均不跳过 retired 节点——可对已 release 的 `bp_handle` 调 `perf_event_enable/disable`（hwbp.c:437-440）→ 悬空句柄 UAF；query/set_override 还可对 retired 节点写入统计/参数（无害但语义混乱）。
- 回答任务书问点「unhook 后断点是否仍触发」：**不会**。unhook 在置 retired 前已 `perf_event_release_kernel(bp_handle)` / `unregister_hw_breakpoint`（hwbp.c:409-413），perf 事件被销毁，硬件断点不再触发；「残余断点未释放 perf 事件」的后果不存在于当前代码。真正的残余问题如上：retired 节点滞留链表，被其它命令路径二次操作。
- 结论：**仍开**（原单并发问题未修；修复引出双重 release 与悬空句柄操作两条新缺陷，建议 unhook 循环加 `if (node->retired) continue;` 并对全部命令路径统一 retired 检查 + 引入锁）。

### AUD-b-5（task 引用 get/put）— **仍开**（主路径已修，失败路径泄漏）

- 已修部分：`hwbp.c:78-79` 新增 `sh_get_task_struct`/`sh_put_task_struct` 符号（kallsyms 解析，hwbp.c:146-147）；`sh_hwbp_hook` 在 find_task_by_vpid 成功后 `sh_get_task_struct(task); node->task_ref = task;`（hwbp.c:362-365）；`sh_hwbp_cleanup`（hwbp.c:600-602）逐节点 `sh_put_task_struct(node->task_ref)` 后再 vfree。线程退出后 task_struct 不再被提前释放，UAF 主路径成立性消除。
- 失败路径审查（任务书点名要求）：
  1. **perf 注册失败路径泄漏引用**：`hwbp.c:376-385`——`perf_event_create_kernel_counter`/`register_user_hw_breakpoint` 失败时执行 `sh_vfree(node); return err;`，**没有** `sh_put_task_struct(node->task_ref)`。get_task_struct 已执行的引用永久丢失 → task_struct 永久泄漏（每次 hook 失败泄一个引用；反复 hook 失败可放大）。
  2. `sh_get_task_struct` 解析失败（hwbp.c:146 为 NULL）时静默跳过 get（hwbp.c:362 `if (sh_get_task_struct)`），整个 AUD-b-5 防护无声失效——`sh_hwbp_resolve`（hwbp.c:133-172）的存在性校验未把这两个符号纳入必需集。
  3. 若 get 成功但 put 符号解析失败（两者独立 kallsyms 查找），cleanup 按条件 `if (node->task_ref && sh_put_task_struct)` 跳过 put——单向泄漏，非 UAF，可接受但应记入。
- 结论：**仍开**（泄漏非崩溃、severity 降为 low-medium，但任务书明确要求"所有失败路径都释放"，答案是否：perf 注册失败路径不释放）。

### AUD-c-2（xperia ctl0 空指针）— **关闭**

- 证据：`xperia_ii_battery_age.c:38-40`：`if (!fg || !fg_sram_write) return -EAGAIN;` 位于 `fg_sram_write(fg, …)` 调用（:42）之前，且 `aging > 5` 早退（:36-37）不受影响。
- 交叉检查：`fg` 全局仍初始化为 NULL（:29）、唯一赋值点 `before_read`（:66），ctl0 在首次 SRAM 读前返回 -EAGAIN 不再解引用。`-EAGAIN` 常量为负，ctl0 语义（失败返回负值）一致。
- 结论：**关闭**。

### AUD-c-3（回调内不自摘钩子）— **关闭**

- xperia：`xperia_ii_battery_age.c:64-67`：`before_read` 改为幂等 `if (fg) return;`，删除了原 `unhook_func(fg_sram_read)`；摘钩仅存在于 `inline_hook_exit`（:89）。回调不再触碰 hook 链。
- qti：`qti_battery_charger.c:66-76`：新增 `static bool qti_battery_hooked;`，`do_init_module_after` 命中自身模块时只置 `qti_battery_hooked = true` 并 `hook_battery_psy_get_prop()`，删除 `unhook_func(do_init_module)`；摘钩移到 `inline_hook_exit`（:103-106）。
- 备注（不开单）：qti 置位发生在 `hook_battery_psy_get_prop()` 返回值检查之前，若该次 hook 失败不再重试（原实现回调每次重入都会重试）——行为弱化但方向保守，属可接受语义变化；`hook_battery_psy_get_prop` 内 `hook_func` 返回值本就未检查（:60-64），维持原状。
- 结论：**关闭**。

### AUD-c-4（panda frida_hide 越界）— **关闭**

- 证据：`frida_hide.c:30-42`：删除 `start[new_len]='\0'` / `saved` 写回；改为 `char line[256]; copy_len = new_len < 255 ? new_len : 255; memcpy(line, start, copy_len); line[copy_len]='\0';` 后对 `line` 做 `strstr`。全程只读 `[m->buf+prev_count, m->buf+m->count)`，`m->count == m->size` 时不再触碰 `m->buf[m->size]`，读/写越界均消除，也不再有竞态写回脏值问题。
- 边界复核：`new_len==0` 早退（:28）保留；`copy_len <= 255` 且 `line[copy_len]` 合法下标。截断到 255 可能让跨 255 边界的匹配串漏检——功能性偏差（block_str 均为短串，实际影响可忽略），非内存安全问题。
- 结论：**关闭**。
