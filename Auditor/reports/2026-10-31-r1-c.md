## 3. 问题单

### AUD-c-1　qti / xperia 的 debug 变体与 release 逐字节相同，且内嵌版本缺少 `_d` 后缀

- **位置**：`modules/KPM/qti_battery_charger/Makefile:41-49`；`modules/KPM/xperia_ii_battery_age/Makefile:41-49`
- **影响**：两个模块的 debug 目标依赖同一个 `objs`（`debug: qti_battery_charger_$(MYKPM_VERSION)_debug.kpm: ${objs}`），`.o` 只按 release CFLAGS 编译一次；且源码中没有任何 `logkd/pr_debug/CONFIG_DEBUG` 门控代码（`grep -rn "logkd\|pr_debug\|DEBUG" modules/KPM/qti_battery_charger/*.c *.h` 为空，xperia 同）。后果：
  1. debug 与 release SHA-256 逐字节相同（复算值见 §1），「变体差异仅日志/断言」的验收前提不成立——按流程这属于「审计未确认差异」，两个变体都必须真机测试或判据作废；
  2. debug 件内嵌 `version=1.0.2` / `1.1.2`（llvm-objdump 实测），违反 debug 版本串应为 `<ver>_d` 的模块规范（panda_hide 的 debug 做对了：独立 `debug/%.o` + `PH_VER=_d`，实测 `version=2.0.0_d`）。
  3. panda_hide 同理存在「debug 无额外日志」的问题：其 debug Makefile 加了 `-DCONFIG_DEBUG` 但源码零处引用，release/debug 仅差版本串与派生重定位共 97 字节（`cmp -l` 97 处，全部位于 `.kpm.info` 区及指向它的重定位；`llvm-objdump -d` 反汇编逐指令 diff 为空）。功能字节完全一致。
- **severity**：medium（影响验收判据与发布物语义，不致崩溃）
- **frequency**：always（每次构建必然如此）
- **confidence**：high（SHA-256 逐字节复算 + 反汇编 diff 实证）
- **验证方法**：`sha256sum` 三对产物；`cmp -l` panda_hide 两变体（97 字节差异定位到 .kpm.info）；`llvm-objdump -d` diff 为空；`llvm-objdump -s -j .kpm.info` 读 debug 版本串。
- **建议修复方向**：qti/xperia Makefile 为 debug 使用独立对象目录并传 `-DQBC_VER/_d` 进编译期版本宏（或对齐 panda_hide 的 `debug/%.o` 模式）；若确认 debug 无独立价值，按规范砍掉 debug 目标并在 metadata 标注 `offset_mode`/变体说明；或给模块源码补充 debug 门控日志使两变体有实际差异。

### AUD-c-2　xperia_ii_battery_age：ctl0 在首次 fg_sram_read 命中前可对 NULL `fg` 解引用，内核崩溃

- **位置**：`modules/KPM/xperia_ii_battery_age/xperia_ii_battery_age.c:31`（`struct fg_dev* fg = NULL;`）、`:33-38`（ctl0 直接 `fg_sram_write(fg, ...)` 无判空）
- **影响**：`KPM_CTL0(inline_hook_control0)` 在模块加载后即可被 supercall 触发；此时若尚未发生任何 `fg_sram_read` 调用（`before_read` 是唯一给 `fg` 赋值的地方，`:60`），`fg` 仍为 NULL，`fg_sram_write(NULL, ...)` 把 NULL 当驱动私有数据解引用 → 内核空指针崩溃。
- **severity**：high（确认可致内核崩溃，不因频率降级）
- **frequency**：low（需在电量计驱动首次读 SRAM 之前恰好触发 ctl0；模块加载早于驱动 probe 完成的时间窗内风险最高）
- **confidence**：high（代码路径静态可复算：全局初始化为 NULL、ctl0 无防护；`fg_sram_write` 符号本身有 `lookup_name` 失败防护，排除另一变量）
- **验证方法**：读源码控制流 + `llvm-readelf` 确认 `.kpm.ctl0` 存在（ctl0 可独立于 init 成功与否被调用）；未做真机复现（按纪律不在审计中加载内核模块）。
- **建议修复方向**：ctl0 入口处 `if (!fg) return -1;`（或先通过一次带保护的探测读取初始化 `fg`）；同时在 ctl0 里校验 `fg_sram_write` 非空。

### AUD-c-3　xperia / qti：在 hook 回调内部摘除自身所在的 hook（KP 明注 unsafe）

- **位置**：`modules/KPM/xperia_ii_battery_age/xperia_ii_battery_age.c:59`（`before_read` 内 `unhook_func(fg_sram_read)`）；`modules/KPM/qti_battery_charger/qti_battery_charger.c:69`（`do_init_module_after` 内 `unhook_func(do_init_module)`）
- **影响**：`hook_unwrap_remove`（`KernelPatch/kernel/base/hook.c:780-798`）在链上所有项清空后 `hook_chain_uninstall(chain); hook_mem_free(chain);`，且源码自带 `// todo: unsafe` 注释。回调正运行在该 chain 的 trampoline 上下文里，摘钩+释放后回调返回路径仍引用已释放内存，存在 use-after-free / 返回地址失效风险；并发调用同一被钩函数时风险更高。
- **severity**：high（可致内核崩溃；属确认性风险）
- **frequency**：low（每模块生命周期只发生一两次；竞态窗口小但真实存在）
- **confidence**：medium（KP 源码明注 unsafe 是静态事实；实际是否崩溃取决于 trampoline 返回路径是否再次访问 chain 内存，未做运行时验证）
- **验证方法**：`hook_unwrap_remove` 实现逐行核读（证据行号如上）；`unhook_func` 宏（`qbc_utils.h:41-46`）仅判 `is_bad_address`，不能防护此场景。
- **建议修复方向**：改为延迟摘钩——回调内只置一个标志，由后续 ctl0/工作项或下一次回调检测标志后再摘；或改用一次性自禁（`args->skip_origin` 永久化 + 保留 chain 至模块卸载）。

### AUD-c-4　panda_hide frida_hide：`is_hidden_map` 对 seq_file 缓冲区 `buf[size]` 的一字节越界读+写

- **位置**：`modules/KPM/panda_hide/src/frida_hide.c:30-31`（`char saved = start[new_len]; start[new_len] = '\0';`）
- **影响**：`start = m->buf + prev_count`，`new_len = m->count - prev_count`；当某次 `show_map_vma` 写满缓冲（`m->count == m->size`）时，`start[new_len] == m->buf[m->size]`，读 + 写各越界 1 字节。seq_file 的 buf 按 `m->size` 精确分配，写入落在内核堆相邻内存，可破坏相邻对象；恢复写回 `saved` 也可能把脏值写回越界位置（竞态下另一 CPU 已改写该字节）。
- **severity**：high（内核堆越界写，可致崩溃/内存破坏/可被布局利用）
- **frequency**：low（仅当 maps 输出恰好填满 seq_file 缓冲边界时触发；大进程 maps 遍历中并非罕见边界）
- **confidence**：medium-high（模块侧代码逻辑确定；是否越界最终取决于目标内核 seq_file 分配策略——部分内核分配 size+1，此处按精确分配判定）
- **验证方法**：静态控制流复算 + 与 `struct seq_file { char *buf; size_t size; size_t from; size_t count; }`（`src/common.h:6-11`）布局比对；未在真机复现。
- **建议修复方向**：先判 `m->count < m->size` 才做临时截断；否则改用 `memchr`/定长扫描（在 `[start, start+new_len)` 内手动匹配，不依赖 NUL）。

### AUD-c-5　qti_battery_charger：本地 `struct module` 布局假设，fallback 路径在部分内核上永远失配

- **位置**：`modules/KPM/qti_battery_charger/battchg.h:142-149`（本地 `struct module { enum module_state state; struct list_head list; char name[64-sizeof(unsigned long)]; }`）；`qti_battery_charger.c:68`（`memcmp(mod->name, MODULE_NAME, sizeof(MODULE_NAME))`）
- **影响**：`mod->name` 的偏移按本地结构体 = `sizeof(state)+pad+sizeof(list_head)` ≈ 24；真实内核若开启 `CONFIG_MODULE_UNLOAD`（含 `module_unload_mutex`）或其它成员，name 偏移不同（如 32），`memcmp` 读到错误偏移 → 永不匹配 → `do_init_module` 钩子既不命中也永不摘除，且 `battery_psy_get_prop` 兜底 hook 永远装不上，模块**静默失效**（不崩溃，但验收若只看「加载成功」会漏判）。这是对内核结构体偏移的隐式依赖，与登记中「该模块不依赖结构体偏移」的说法不符。
- **severity**：medium（功能静默失效 + 与无偏移依赖声明矛盾）
- **frequency**：depends on target kernel（无偏移依赖的内核上不触发）
- **confidence**：medium（本地结构体与上游 4.x/5.x `struct module` 的差异是确定事实；具体目标内核是否受影响未核实——未获取目标内核 `struct module` 布局证据）
- **验证方法**：本地结构体成员逐项与 KP 子模块内及上游通用定义比对；`memcmp` 长度 20 < name[56] 不会越界（排除崩溃面）。
- **建议修复方向**：不用 `mod->name` 结构体偏移，改 hook `battery_psy_get_prop` 符号出现时机（如 `notify_modules_event`/`load_ap_kpm_modules` 事件机制，KP 已导出 `notify_modules_event`），或对 name 匹配改用带偏移确认的动态推导。

### AUD-c-6　panda_hide debugger_hide：`after_proc_pid_wchan` 对非 NUL 保证的 seq_file 缓冲做 strcmp，且未校验 size

- **位置**：`modules/KPM/panda_hide/src/debugger_hide.c:34-43`
- **影响**：`strcmp((char*)m->buf, "ptrace_stop")` 假设 `m->buf` 以 NUL 结尾——seq_file 不保证；`m->count == m->size` 时 strcmp 会越过有效数据继续读，功能上可能失配，极端下越过分配边界。另外 `m->buf[0]='0'; m->buf[1]='\0'; m->count=1;` 未校验 `m->size >= 2`（实际 seq_file 最小分配远大于 2，风险低）。`after_do_task_stat`（`:45-56`）用 `i + 2 < m->count` 有界扫描，无此问题。
- **severity**：low
- **frequency**：low
- **confidence**：medium（strcmp 依赖 NUL 的事实确定；越出分配需要缓冲恰好写满）
- **验证方法**：源码控制流 + 与同文件有界写法对比。
- **建议修复方向**：与 AUD-c-4 相同，改为 `[0, m->count)` 定长比较（如 `memcmp(m->buf, "ptrace_stop", 11) == 0 && m->count == 11`）。

### 3.4 备注项（不开单）

- **panda_hide mem_hide 的 `args->ret` 用法：Developer 线索不成立。** Developer 提示「`mem_hide.c` 用 `args->ret` 当擦除长度（上游用 `args->arg3`）疑似错」。审计以 `KernelPatch/kernel/base/hook.c:435`（`fargs.ret = origin_func(...)`）确认 `args->ret` 就是 `access_remote_vm` 的真实返回值（实际读到/写入的字节数），`mem_hide.c:66-71` 用 `ret` 截断 `len`、`ret<=0` 早退，比直接用请求长度 `arg3` **更正确**。判定：无问题。
- **panda_hide net_hide 缺 `__get_task_comm` 时放行逻辑**：`net_hide.c:55-57`，符号缺失时 `comm` 全零 → `strstr` 失败 → 一律拦截 frida 端口（含 adbd）。方向偏保守，只造成 adbd 无法连 27042 等端口的功能退化，非安全问题，不开单；建议在报告中由 Developer 确认为有意行为。
- **三个模块 ctl0 无 uid 二次门**：触发面受 APatch supercall 自身鉴权约束，不构成本模块层的绕过；xperia 的 ctl0 可直接改电池老化寄存器，建议文档标注「ctl0 = 特权操作」。
- **panda_hide ctl0 `compat_copy_to_user` 返回值被忽略**（`main.c:41`，函数带 `__must_check`）：拷贝失败时用户拿不到回显但无内核副作用，不开单。
