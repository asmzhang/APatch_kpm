## 3. 现在这一件事：`zram_zstd` 1.0.2 / `AUD-107`

### 3.1 问题是什么

`modules/KPM/zram_zstd/zs_display.c` 有两处 `hook_wrap`：

- `:55` `hook_wrap(zcomp_available_show, 2, NULL, zstd_list_after, NULL)`
- `:86` `hook_wrap(do_init_module, 1, NULL, zram_module_after, NULL)`

`zram_zstd_exit()` 在 1.0.1 只调了 `crypto_unregister_alg`，**这两个 hook 一个都没摘**。而 KP 的
`unload_module()` 全文没有 hook 清理，`kp_free_exec()` 只是 TLSF 块回收（不清零、不 unmap）。
后果：卸载之后**任何一次 LKM 加载**（`do_init_module`）或读 `/sys/block/zram0/comp_algorithm`
（`zcomp_available_show`）都会跳进已回收、可能已被复用的镜像块 → UAF / panic，且非特权可触发。

铁证：1.0.1 卸载后再加载，dmesg 报 `algorithm list hook failed: -4094` 与
`module load hook unavailable`；`-4094 == HOOK_DUPLICATED`（`KernelPatch/kernel/include/hook.h:18`、
`hook.c:703`），说明第一次的 hook 还在原处。

### 3.2 已完成的修复（工作树里，未提交）

- `zs_display.c`：新增 `display_show_target` / `display_init_target` 记住两个 hook 目标；
  新增 `stop_zram_display()`，用

### 7.3 反复踩的坑

- **CRLF**：`modules/KPM/**` 多个文件是 CRLF。用 Python 改源码时「读归一 `\n`、写回 `\r\n`」，
  否则 `assert s.count(old) == 1` 得 0。
- **Python 多层转义**：改 C 字符串时 `\\n` 会被吃成真换行 → 先写 `.py` 文件，用 `BS = chr(92); NL = BS + "n"` 拼。
- **`adb push`**：必须 `MSYS2_ARG_CONV_EXCL='*' adb push`，否则 `/data/local/tmp/` 被 MSYS 转成本机路径。
- **`make` 不覆盖已有产物**：`re_kernel/Makefile:65` 的 `@test ! -e $@` 会静默失败 → 先 `rm -f *.kpm *.kpm.json`。
- **`zram_zstd` 的 `out/`**：已存在时 `prepare_codec.py` 抛 `ValueError` → 先挪走。
- **`kpmctl unload` 用注册名**（`KPM_NAME`，如 `re_kernel`），别名 `rk` 会 `rc=-1`。
- **设备上加载前先看 `kpmctl list`**：`nomount` / `run_cmd_demo` 是设计内常驻、不可卸载，只能重启清掉。
- **真机死机不自救**：遇到硬重启/卡死，立即停手，采集证据（`/sys/fs/pstore/`、主机侧
  `adb shell su -c 'cat /dev/kmsg' > log` 流式抓取），然后通知维护者；禁止反复重试、禁止改偏移硬上。

## 10. 判据与纪律（别越线）

- **不替别人写结论**：修复者不能自己关单，`closed_by != owner`，门禁强制。
- **身份只追加**：`builds[]` 只追加，旧构建记录、已归档产物与 `MANIFEST.json` 不可覆盖；核验按记录绑定的 `source_commit`。
- **交接必须从冻结提交构建**：脏树会被拒，只能 `--allow-dirty` 记 `exploration`。
- **不猜偏移**：推导失败就走降级或报错，禁止按内核版本号分支。
- **公开文件不写本机信息**：不写本机绝对路径、设备序列号、superkey；测试报告用设备指纹哈希代替序列号。
- **不为了过门禁而放宽断言**：断言/用例/检查范围任何缩小都要在报告里写明理由，并由 Auditor 独立复核。
- **判据与机制分流**：让共享工具支持模块的合法结构变化归需要它的角色直接实现（补正反夹具 + 同轮提案 + 维护者逐字节复核），不改判据。
