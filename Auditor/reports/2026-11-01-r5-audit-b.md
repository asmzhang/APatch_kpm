## 逐项核查结论

### 1. MSR 直写的正确性（重点）

核对结果（hwbp.c 行号以 f96b6d58 为准）：

- **对齐**：`sh_hwbp_rearm_msr` 对 old/dst 均 `& ~3ULL`（hwbp.c:302-303）。AArch64 指令天然 4 字节对齐，LR 恒 4 字节对齐，DBGBVR 的 bits[1:0] 被 BE 匹配逻辑忽略，因此 4 字节对齐写 BVR 是正确的（8 字节对齐并非 BVR 要求，BVR 是 64 位寄存器本身天然按 8 字节访问）。**通过**。
- **BCR 位域处理**：不清重编 LEN/TYPE/PAC，而是 `bcr = read; write(bcr & ~1); write_bvr(dst); write(bcr)`（hwbp.c:318-324）——保留原 E 以外的所有位（含 HMG/PMC/LBN/BT/PAC），只翻 E 位。这是对「原三件套语义等价」最保守的实现，避免模块自行拼 BCR 位域出错。**通过**。
- **写序**：清 E → 写 BVR → 恢复 BCR（hwbp.c:322-324），符合 ARM ARM「修改 BVR 前先 disable」的推荐顺序。**通过**。
- **同步**：写后 `isb`（hwbp.c:327、355）。自托管调试寄存器修改后 isb 同步指令流即可，dsb 非必需（无内存共享语义变化）；未观察到缺 isb 的路径。**通过**。
- **STRIP_PAC**：所有取自 regs->regs[30] 的 LR 都过了 `STRIP_PAC`（hwbp.c:41 定义；412、458、508 使用）。**通过**。
- **槽位数**：`ID_AA64DFR0_EL1.BRPs`（bits[15:12]，实现数-1，+1 封顶 16）（hwbp.c:289-294），访问限定在已实现槽内，避免访问未实现寄存器二次陷入。**通过**。
- **跨 CPU**：rearm 总是发生在被断点命中的目标线程的调试异常上下文中——此刻目标线程就在当前 CPU 上，MSR 写的就是目标线程将 ERET 回的那个 CPU 的 BVR/BCR，**无需 IPI/pin**。这一点设计上是自洽的。**通过**（前提：节点按线程注册，`perf_event_create_kernel_counter(attr, -1, task, ...)` hwbp.c:583，事件跟随单线程）。
- 残留：`sh_dbg_init_slots` 只在 `sh_hwbp_init`（stealth_hook_init 内）调用；`sh_hwbp_hook` 的懒初始化分支（hwbp.c:525-528）只初始化链表不补 slot 初始化。由于 syscall hook 注册在 init 末尾（stealth_hook.c:321），此分支正常不可达；但 slot_count=0 时 `rearm_msr` 走 `!total` 分支只改 node->bp_addr 不动寄存器（hwbp.c:308-311），一旦该分支可达即复现「断点留原地自旋」。评级 info（防御性缺陷）。

**AUD-B-1（high）** 同址断点被 BVR 值匹配误伤：rearm/disarm 按「本 CPU 上 BVR==old 且 BCR.E==1」匹配槽位，而非按本节点自己的槽位匹配。

- 位置：hwbp.c:312-326（rearm）、hwbp.c:343-354（disarm）。
- 机制：BVR/BCR 是 per-CPU 寄存器，perf 分配的槽位对模块不可见，只能按值匹配。当两个节点 hook **同一地址**（允许：sh_hwbp_hook 无去重，hwbp.c:555-603），或另一进程/另一 perf 用户恰好同址武装断点时，rearm 节点 A 到 LR 会把同 CPU 上所有 BVR==原地址的槽全部改写（含节点 B 的槽，被改成 A 的 LR）；`sh_hwbp_disarm_msr` 更危险：会把同址其它节点的 BCR.E 清零且 perf 层不知道，**其它节点永久静默**（perf 以为还武装），且 unhook/disable 任意一个节点都会误伤全部同址节点。
- 证据：匹配循环无任何节点/事件归属过滤，hwbp.c:315-324 只比较 `sh_dbg_read_bvr(n) != old`；同址多节点可由重复调用 SH_CMD_HWBP_HOOK 构造（无去重，hwbp.c:535-603）。
- 修法建议：为每节点记录 perf 事件内建的槽位（可由 attr->bp_addr + 事件创建后读 debug fs，或在 hook 时记录创建后实际武装的槽），rearm/disarm 只操作自己的槽；最低成本替代：禁止同 (addr,tid) 重复 hook（去重返回 -EEXIST），并把 disarm 匹配收紧为「本节点的 BVR 当前值」由状态机维护。真机上 R5 若用例不含同址重复 hook，可先以限制用例缓解，但缺陷必须开单。

**AUD-B-2（medium）** MSR 直写与 perf 状态失同步（两半，第一半实现方已承认）：

- (a) `perf_event` 内部 `info->address` 不更新，线程被切出再切回 / 迁移 / 热插拔 / 休眠唤醒时 perf 按 info->address 重装 BVR，断点回落旧地址（代码自述：hwbp.c:242-246）。入口拍回落会在下次调用再命中并自愈；但 **SKIP_ORIGIN/MODIFY_ARGS 节点**回落旧地址 = 每次函数入口重命中被再次跳过/改参，行为仍在；真正的坏情况是 `is_waiting_return==1` 时断点回落原址：函数体尚未返回就命中入口，handler 走 `is_waiting_return` 分支把当前 X0 当返回值记下（hwbp.c:448-452），错采一拍且 is_waiting_return 清零后真返回不再捕获——与注释「最多错采一拍」一致，不崩溃。
- (b) 实现方注释**未提及**的一半：进程上下文的 `sh_hwbp_enable(enable=0/1)` 走 `perf_event_disable/enable`（hwbp.c:658-664），而 handler 在异常上下文直接翻 BCR.E——两条路径并发写同一 BCR 无互斥（命令持 mutex，handler 无锁）。disable 的 IPI/上下文切换延迟窗口内，目标线程每次命中都会进 handler 且因 `is_disabled` 直接 return（hwbp.c:392、400-403），ERET 回原 PC 立即重触发，形成短暂调试异常自旋，直到 perf 的 disable IPI 到达清 E。宽窗口很窄，但与 (a) 叠加可能产生长时间错位。
- 修法建议：enable/disable 也走 MSR 直写（与 rearm 一致的寄存器真值），或在 node 上加 per-node 原子状态让 handler 与命令路径对「寄存器应为武装/解除」达成单一写者。至少把 (b) 写进 README 的已知局限。

**AUD-B-3（medium）** unhook / cleanup 释放前未 disarm（NEW-g-1 确认存在）：

- 位置：hwbp.c:626-633（unhook 直接 release，无 disarm）、hwbp.c:820-836（cleanup 对未 retired 节点同样直接 release + vfree，无 disarm）。
- 机制：release 理论上由 perf 内部同步（perf_event_release_kernel 会 disable 并等待 in-flight 回调；该同步行为**未核实**，尤其 `sh_unregister_hw_breakpoint` 回退分支 hwbp.c:629-630）。若同步缺口存在：handler 正在执行时节点被 vfree → UAF；或 release 后 BCR 仍武装一拍，配合 AUD-B-1 的值匹配可能残留武装槽。
- 修法建议：release 前先 `sh_hwbp_disarm_msr`（按节点地址清 E，成本一行），并在报告中补 `perf_event_release_kernel`/`unregister_hw_breakpoint` 对 in-flight overflow handler 的同步证据（读内核源码，不猜）。

**AUD-B-4（low）** handler 归因 fallback：`(!matched || matched->is_disabled) && active == 1` 时把命中归给唯一活跃节点（hwbp.c:385-399）。在「节点被 disable 但其断点尚未被 perf 真正解除」的窗口（正是 AUD-B-2b 的窗口）里，本应被忽略的命中会落到另一节点头上，污染其 hit_count/entry_args。修法：去掉 fallback，unmatched 只计数。

**AUD-B-5（low）** 重复 hook 同一 (addr,tid) 无去重（hwbp.c:535-603）：第二个节点占第二个槽但同址只触发一次异常，第二节点永远无数据，且是 AUD-B-1 误伤的触发器。修法：入口去重返回 -EEXIST。

**AUD-B-6（low/info）** 状态机中途事件的收敛性核对：unhook 置 `retired=1, is_disabled=1` 且 `bp_handle=0`（hwbp.c:633-636）后，handler 因 `!node->retired` 不再匹配（hwbp.c:388、392），状态不会写已退役节点；enable/disable/override/skip 均跳过 retired（hwbp.c:653-654、692-693、757-758、790-791）。递归/嵌套调用：入口拍断点挪 LR 后，同函数递归的内层返回恰好命中 LR 槽，内层返回值被当作外层返回值记下（错采，不崩溃）——README 已记「错采」局限（0ebc077 提交说明），评级 info。

### 2. 异常上下文睡眠审计（逐行）

hwbp_handler（hwbp.c:374-516）调用面：链表遍历（无锁，靠 retired 标志，hwbp.c:166-168 注释）、MSR 读写、`sh_copy_from_user_nofault`（nofault，hwbp.c:498-499）、pr_warn/pr_err、寄存器改写。**无分配、无 mutex、无非 nofault usercopy、无可能睡眠调用**。`sh_addr_is_valid` 的 `access_remote_vm` 路径（hwbp.c:113-127）只在 hook 入口（进程上下文、mutex 内）到达。dump 兜底睡眠已被 39c8254 根治：缺 nofault 符号直接禁用 dump 并告警一次（hwbp.c:488-497）。8654cd0 修复的 sh_dbg 参数错位已核实（diff 中 modify=%llx 已删）。**通过**。

### 3. 生命周期与 cleanup 顺序

`sh_hwbp_cleanup`（hwbp.c:810-840）：release → 摘链 → put_task_struct → vfree，顺序正确；`sh_hwbp_exit` 先 `inline_unhook_syscalln` 再 `sh_hwbp_cleanup`（stealth_hook.c:452-463），顺序正确（AUD-e-4 回归已修复）。缺陷即 AUD-B-3（缺 disarm）。ghost 侧：卸载不 munmap、只回收记账（ghost_mem.c:244-267），有意识决策并写明理由，info。

### 4. 权限门

- hwbp 组（0x1001–0x1007）与 ghost 组（0x3001–0x3004）非 root 一律 -1（stealth_hook.c:145-154）；syscall 入口对非受信 uid 直接 skip_origin=-1（stealth_hook.c:289-293）。默认受信表 {0, 2000}（stealth_hook.c:40-41）。
- PTE 组命令对任意受信 uid 开放但恒返回 -95（stealth_hook.c:168-175），无信息泄露。
- **AUD-B-7（low）** ctl0 的 `allow:<uid>`/`deny:` 无调用者权限检查（stealth_hook.c:410-428）：任何能通过 APatch ctl0 通道的调用者（默认需 superkey，即 root 等价）可扩 allowlist。被扩入的 uid 只能获得 STATUS/ECHO/PTE_QUERY（hwbp/ghost 组仍被 uid!=0 门拦住，stealth_hook.c:145-153），实际增益有限。修法：allow:/deny: 要求 uid==0。

### 5. /proc 可见性副作用

- **AUD-B-8（low）** ghost alloc 建的匿名 VMA 不隐藏，/proc/pid/maps 可见（ghost_mem.c:10-13 明示，需配合 memcrc RANGE 规则）——相比上游是可检测痕迹的回退，且「是否隐藏」从模块侧不变量变成运维约定。文档已声明，评级 low。
- 硬件断点本身不产生 ptrace/proc 痕迹（无 PTRACE_ATTACH、无 /proc/pid/status TracerPid 变化）——由代码路径核实：全模块不调 ptrace 系符号（grep 无命中，kallsyms 解析表 hwbp.c:74-87、ghost_mem.c:42-51 中无 ptrace）。
- debug 变体仅多 sh_dbg 日志（stealth_hook.h:23-27），符合「变体差异仅日志」的门禁假设。

## 结论

**有条件进入 R5 真机矩阵**：MSR 直写的核心正确性与异常上下文安全（本次重点）核实通过，可以在真机上测；但 AUD-B-1（同址断点误伤，high）必须在 R5 用例中显式排除「同一 (addr,tid) 重复 hook」与「同址多节点」场景并在矩阵中标注该限制，同时 AUD-B-3 的 release 同步性需在读内核源码后补证；AUD-B-1/AUD-B-3 修复前不应宣称 stealth_hook 支持多节点并发 hook。若 R5 计划包含同址多节点用例，则本模块**暂不进入** R5。
