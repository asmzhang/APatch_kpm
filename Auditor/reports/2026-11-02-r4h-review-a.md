## 1. AUD-B-1（high）：去重键 (addr, tid) —— **部分修好**

**已做到的：**

- 新增 `hwbp_find_node(addr, tid)`（`hwbp.c:524-543`）：跳过 `retired` 节点，`tid==0` 通配（实际 hook 入口恒传 `req.target_pid`，非 0，`hwbp.c:555` 已拒绝 `target_pid==0`），按 `(target_addr, tid)` 精确匹配。**同一线程同一地址不可能再出现两个节点**——`sh_hwbp_hook` 在分配节点前查重（`hwbp.c:576-594`），全链路只有这一处建节点入口（ghost/pte 路径不建 hwbp 节点），无绕过路径。retired 节点被 `find_node` 跳过，unhook 后重挂同址会建新节点、旧 retired 节点由 cleanup 释放，符合设计。
- 同参幂等返回 0、异参返回 `-17`(-EEXIST) 并 `pr_err` 打印现存 flags（`hwbp.c:589-593`）。

- 多线程同址（不同 tid）合法多节点保留，CLI 默认 tid=gettid、`--tid all` 映射 0（`stealth_cli.c:143-147`），语义正确。

**发现的问题：**

**AUD-B-2-1（medium）幂等判断是单向子集比较，「参数不同返回 -EEXIST」契约被打破**

- 位置：`modules/KPM/stealth_hook/hwbp.c:589`
- 证据：判等条件为
  ```c
  if ((dup->flags & (req.flags & mask)) == (req.flags & mask) && ...)
  ```
  只要求 `req.flags ⊆ dup->flags`。先 `hook --listen-ret` 再重复 `hook`（不带 `--listen-ret`），flags 不同（`0x9` vs `0x1`），却命中幂等返回 0；`MODIFY_ARGS`/`SKIP_ORIGIN`（bit7/bit8，`stealth_hook.h:54-55`）不在 mask 内，同理性返回 0——但 SET_OVERRIDE 加上的 SKIP_ORIGIN 是行为性 flag，用户得到的 0 与现有节点实际配置并不一致，静默「假装成功」正是本单要消灭的失败模式（消息文本自己写着「静默覆盖会让先挂的那个节点失去归属」）。
- 影响：重复 hook 以更少 flags/不同 trampoline 意图重挂时被误判幂等，调试者误以为新配置生效。非内存安全问题，但违背本条修复声明的契约（「参数完全相同返回 0」≠「参数是子集返回 0」）。
- 建议修法：改为双向相等 `(dup->flags & mask) == (req.flags & mask)`；若有意让 MODIFY_ARGS/SKIP_ORIGIN 不参与判等（它们只能经 SET_OVERRIDE 设置），应在注释里写明并把这两个 bit 从比较里显式清掉，而不是靠 mask 恰好不含。
- mask 覆盖性核对：影响槽位分配/武装的字段 EXECUTE/READ/WRITE/INLINE/NO_AUTO_ENABLE 均在 mask 内 ✔；`dump_size` 用 `SH_DUMP_MAX` 钳制后比较，与建节点时的钳制（`hwbp.c:645`）一致 ✔；`trampoline_addr` 参与比较 ✔。

**关于「rearm/disarm 按 BVR 值找槽会否误伤同址第二个节点」：** 逻辑上依赖一个未在源码层逐行核实的前提——perf 的 per-task 用户断点只在任务被调度到该 CPU 时布防，因此任一 CPU 任意时刻 BVR==old 的武装槽只属于当前运行线程的那个节点；同址不同 tid 的两个节点不会在同一 CPU 同时武装，`sh_hwbp_rearm_msr`（`hwbp.c:297-329`）/ `sh_hwbp_disarm_msr`（`hwbp.c:334-356`）的全槽扫描就退化为唯一匹配。同任务双节点已被本次去重消灭。此前提未核实（未读内核 perf 调度布防源码），标记为**未核实**；真机 dedup/multi/states 探针通过是经验证据而非源码证据。若该前提不成立（例如事件在迁移后未及时摘除的窗口），BVR 值匹配仍可能挪错槽——建议后续轮把 rearm/disarm 的匹配键改为「节点→perf 事件→该事件自己的 slot 映射」以彻底消除值匹配。

## 3. 本轮回归：返回值语义 —— **部分修好**

- 命令分发 `stealth_hook.c:192-209`：unhook/enable/disable/set_skip 均直接透传返回值，无包装，✔。
- CLI `stealth_cli.c`：`cmd_unhook`（`:270-277`）、`cmd_enable`（`:290-300`）、`cmd_skip`（`:483-489`）均为 `rc < 0 → die()`，0 匹配时内核返回 -1/-2，`die` 对 libc 折叠的 `rc==-1` 用 errno 报错——**没有把「0 个匹配」当成功的路径** ✔。`cmd_list`（`:317-355`）`rc<0 且 index==0` 判空表打印提示，`index>=total` 退出，逻辑正确。
- **AUD-B-2-2（low）set_skip 未按契约返回影响个数**：
  - 位置：`modules/KPM/stealth_hook/hwbp.c:858`
  - 证据：`return found > 0 ? 0 : -2;`，found 未回传。修复说明与任务契约均写「unhook/enable/disable/set_skip … 返回影响个数」，unhook/enable 做到了，set_skip 没做。
  - 影响：CLI `skip: rc=0` 无法告知影响几个节点（tid=0 通配时尤其）；与同轮其余命令语义不一致。
  - 建议修法：与 enable 一致改 `return found;`，无匹配返回 -1/-2，CLI 打 `changed=%ld`。
