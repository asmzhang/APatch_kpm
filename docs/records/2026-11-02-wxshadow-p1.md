# wxshadow P1：双视图（PTE 切到影子页）

日期：2026-11-02。对象：`Developer/tools/wxshadow-probe/`（探针，不是成品模块）。
前置：P0 已验证「pid → leaf PTE → 物理地址 → 内核可读」这条路（见 [2026-11-02-wxshadow-p0.md](2026-11-02-wxshadow-p0.md)）。

## 1. 这一步要证明什么

P0 只证明「能看见目标进程的页」。P1 要证明「能让目标进程看见另一份内容，并且退得回去」：

1. 把目标进程某一页 4 KiB 匿名页的 PTE 指向我们自己分配的一页（影子页），影子页里保留原内容但改了几个字节；
2. 目标进程读同一个虚拟地址，读到的是影子页的内容；
3. `release` 后 PTE 回到原值，目标进程读回原内容，影子页释放；
4. 全过程 dmesg 无 BUG / Oops / 锁告警，`unload` 不留残留。

## 2. 实现（`wxs_probe.c` 0.0.2）

状态机：`none(0) → attached(1) → installed(2)`，`attach` 时 `get_task_mm()` 持有 mm 引用，`detach`/`exit` 时 `mmput`。

- `attach <pid> <va>`：`find_task_by_vpid` → `get_task_mm` → `pgd = *(mm + mm_struct_offset.pgd_offset)` → `pgtable_entry(pgd, va)`；要求 `PTE_VALID` 且 `(pte & PTE_TYPE_MASK) == PTE_TYPE_PAGE`（只收 4 KiB leaf），记下原 PTE 与 `va & 0xfff`。
- `install <hexbytes>`：`__kmalloc(4096)` 并要求页对齐 → 从原物理页整页复制 → 在页内偏移处写新内容 → `dc cvau` 逐行清到 PoC → `at s1e1w` 取影子页物理地址 → 新 PTE = 原 PTE 属性位保留、只换 `[47:12]` 输出地址 → 写 PTE → `dsb ishst` → TLBI → `dsb ish`/`isb`。
- `release`：确认当前 PTE 仍是我们装的那一个（不是就不动，报 `pte changed`），写回原 PTE，同样 TLBI，`kfree` 影子页。
- TLB：用 `VAAE1IS`（by VA、All ASID、EL1、inner shareable）。目标 mm 可能同时在别的核上跑，按 ASID 精确刷反而会漏，所以整 ASID 一起刷。VA 编码与内核 `__TLBI_VADDR` 一致（`va>>12` 取低 44 位）。

## 3. 结果（两台，同一份 18296 B 产物，`und=10`，两形态 0 缺失）

| 设备 | 形态 / 管理器 uid | attach | install | 目标进程读到 | release 后 |

| Pixel 6 `sha256:433ab88276ec`（6.1.99-android14） | kernel / 10273 | `pte=0xe80009dfa31f43` | `shadow_pa=0x8ce4be000`，`pte → 0xe80008ce4bef43` | `534841444f572d7031…`（`SHADOW-p1`） | PTE 回 `0xe80009dfa31f43`，内容回 `4f524947494e414c…` |
| 小米 13 `sha256:cdc3e9167b02`（5.10.149-android12-9，`kernelpatch-lkm`） | lkm / 10270 | `rc=0` | `rc=0` | `534841444f572d7031…` | 内容回 `4f524947494e414c…` |

- 两台 `load rc=0` / `unload rc=0`，dmesg 无 BUG、无 Oops、无 `__list_del_entry_valid`。
- 判据全部达成：目标进程读到影子内容、模块侧 `probe` 读到同一页同一份内容、`release` 后逐字节复原且 PTE 回原值、卸载无残留（`wxs_detach()` 兜底）。

## 4. 两个踩坑

1. **页内偏移丢失**：`attach` 里把 `wxs_tva` 直接掩成页基址，`install` 又用 `wxs_tva & 0xfff` 算偏移 → 恒为 0，补丁写在了页首而客户端读的是 `+0x100`，于是「PTE 换了、内容没变」。修法：单独存 `wxs_toff = va & 0xfff`。教训：PTE 级切换成功不代表数据改动生效，判据必须落在「目标进程读到什么」。
2. **客户端没重编**：`make clean` 会删掉 `wxs_client`，只跑 `make all` 就把旧二进制推上去了，导致日志文件根本没生成。修法：`make client` 单独目标，脚本里先 `ls -l` 确认时间戳。

## 5. 已知限制（P2 再处理）

- 只处理 4 KiB leaf；huge/block/table 一律拒绝（与上游一致，上游还要再拆 huge PMD）。
- **没有取 `mmap_lock`**：KP 没有导出 `mm_struct` 的 `mmap_lock` 偏移，探针只在「目标页不被 munmap/mremap」的前提下工作；客户端是单线程只读，够用，但这不是可交付形态。P2 要么补偏移推导，要么按上游那样做 mm 级准入门。
- 只做**数据视图**：影子页与原页同样是可读写，没有 UXN/执行视图，也没有 icache 同步（P2 的 UXN fault 与 `STEPPING` 态才需要）。
- 没有 generation/token，多个客户端同时 attach 会互相覆盖（单实例状态机）。

## 6. 下一步（P2）

按 [2026-11-02-wxshadow-feasibility.md](2026-11-02-wxshadow-feasibility.md) §7 的判据：

1. 用 **UXN fault**（源 PTE 置 UXN → 执行时 IABT）代替显式 `install` 触发，处理程序里切到影子页；
2. 加执行视图：`BRK` 单步（ABI 已在 P0 探针验过）跑被替换的指令再切回；
3. 生命周期：in-flight 收拾、`exit_mmap`/`copy_process` 钩子、卸载时确保没有线程停在影子页上；
4. 再做一次「App 自查」演示：目标进程读自己的代码段，看到的是原字节。
